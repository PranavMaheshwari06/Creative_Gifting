# Project Brief — Creative Gifting

## 1. Business context
Family business run by the owner's mother: premium gift packing for Indian occasions.
Services: wedding trousseau packing, shagun/return-gift packing, newborn and baby-shower gifting,
festive gifting (e.g. Diwali, Raksha Bandhan), corporate gifting, customised gift packaging.
Target market: upper-income Indian families, wedding planners, NRIs gifting to India, corporates.
Website goals, in order: (1) show the quality of work, (2) generate WhatsApp/phone/form enquiries,
(3) look and feel like a luxury brand run by a top agency, (4) be effortless for the owner to update.
Primary business channel today = word of mouth. Instagram is being started alongside this site;
the site and Instagram must feel like one brand.

## 2. Original requirements (from the owner, verbatim intent)
Portal "Creative Gifting": marketing site to showcase portfolio and generate enquiries/leads.

### Admin
- Secure login, 2 steps: (a) user-id + password + 4-digit captcha, then (b) a random 4-digit OTP
  generated by the portal and emailed to a pre-configured email address.
- Add / edit / delete portfolio items (images with descriptions).
- Create and manage categories (Wedding, Baby Shower, Festive, Corporate, ...) per item.
- Update homepage banner, text content, menus, contact details.
- View and manage customer enquiries.

### Visitors
- Browse portfolio in a gallery; filter/search by category and keyword.
- View detailed description of each item.
- Enquiry form: Name, Phone, Email, Occasion Type, Occasion Date, Message.
- WhatsApp and click-to-call options.

### Pages
Home (banner, highlights, call-to-action), Portfolio/Gallery, About Us, Contact Us.

### UI/UX
Modern, visually appealing, mobile responsive; smooth scrolling; clean layout; grid gallery with
clickable detail view; configurable menu/navigation; prominent "Request a Quote" buttons.

### Extras
Testimonials section; social media links; basic search + category filtering.

### Assets (arriving later)
Square logo + rectangular banner images go into placeholders. Build the placeholders so they can be
swapped from the admin without code changes.

## 3. Additions agreed in planning (v1 scope)
- Admin is a mobile-first installable web app (PWA) designed for a non-technical user: see
  docs/ADMIN_FOR_MOM.md. This is a top priority, equal to the public site.
- Enquiry management: status (New / Contacted / Booked / Closed), notes, call and WhatsApp buttons,
  instant email alert to the owner, CSV export.
- Testimonials, social links and menu are admin-editable.
- SEO foundations: sitemap, robots, Open Graph images, LocalBusiness structured data, per-item URLs.
- Analytics (privacy-friendly) + tracking of WhatsApp/call/form clicks as events.
- Privacy policy + consent checkbox.
- Spam protection on the enquiry form (honeypot + rate limit; Cloudflare Turnstile optional).

## 4. Out of scope for v1 (do not build, but don't block)
Online payments/cart, customer accounts, multi-admin roles, automated WhatsApp messages (needs the
WhatsApp Business API), automatic Instagram posting, AI-written captions. Keep the design open to these.

## 5. Data model (starting sketch; refine in Phase 1)
AdminUser, Category (name, slug, order, active), PortfolioItem (title, slug, description, category,
tags, featured, status draft/published, order, created/updated), PortfolioMedia (item, url, alt,
order, type image/video), Enquiry (name, phone, email, occasionType, occasionDate, message, status,
notes, source, createdAt, consent), Testimonial (name, city/occasion, text, photo?, active, order),
SiteSettings (single row: hero media + headline + subline, about text, contact details, WhatsApp
number, social links, SEO defaults), MenuItem (label, href, order, visible),
LoginChallenge (captcha/OTP state), TrustedDevice, AuditLog (admin actions).
Soft delete everywhere (a "trash" for 30 days) — mom must be able to undo mistakes.

## 6. Admin authentication spec
Step 1: user-id + password + captcha.
- Captcha: 4 characters, generated server-side, rendered as an SVG/image, stored hashed server-side,
  single use, expires in 2 minutes, refreshable. No answer ever sent to the browser in plain text.
- Password: Argon2id. Generic error messages ("details don't match").
Step 2: OTP.
- 4 digits from a cryptographically secure RNG, emailed to ADMIN_OTP_EMAIL (environment variable).
- Stored hashed, single use, expires in 5 minutes, max 5 attempts then 15-minute lockout,
  resend cooldown 60 s, max 3 resends per login attempt.
- Rate limits per IP and per account on both steps. All attempts audit-logged.
Session: HttpOnly, Secure, SameSite=Lax cookie; sliding 30-day expiry for the owner's phone.
Because a 4-digit OTP is inherently weak, the attempt limit, short expiry and lockout are mandatory.

## 7. Decisions to confirm with the owner (defaults in bold)
- D1 Trusted phone: after a full login, **skip the OTP on that phone for 30 days** (password still
  needed; revocable in settings). Keeps security, removes daily friction for mom.
- D2 Admin language: **English + Hindi toggle** (public site English; Hindi version later).
- D3 Categories: **one primary category + optional tags** per item.
- D4 Media: **multiple images per item, one optional short video**.
- D5 Hosting: Vercel + managed Postgres in a Mumbai/India region where available. Verify current
  pricing and terms (free hobby tiers may not permit commercial use).
- D6 Analytics: **Plausible or GA4** (decide in Phase 1; privacy-friendly preferred).
- D7 Who receives the OTP email: ____ (mom's own email, or the developer's)
- D8 Show pricing? **"Starting from" ranges or none; never hide completely if mom is comfortable.**
- D9 City / service areas for local SEO: ____
- D10 Enquiry alerts: **email + admin push notification** (WhatsApp automation = v2).

## 8. Success measures (first 90 days after launch)
Mobile Lighthouse >= 90; mom completes all "Mom test" tasks unaided; >= 15 qualified enquiries per
month by month 3 (adjust once we have a baseline); every enquiry answered within 2 hours in
business hours.
